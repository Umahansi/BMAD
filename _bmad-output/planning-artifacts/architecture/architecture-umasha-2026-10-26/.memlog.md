- (decision) Project umasha; architecture workspace architecture-umasha-2026-10-26 under planning-artifacts/architecture, ignoring configured project_name 'BMAD Project'. Built on final brief and PRD.
- (direction) User said stop asking questions: Fast path, gaps filled with [ASSUMPTION] tags. Spine-only deliverable assumed (purpose/audience question not asked).
- (constraint) From PRD: web app, single user, one screen, no server, no Task data over network (FR-5, Private NFR); 320px responsive, keyboard + WCAG 2.1 AA, <100ms, evergreen browsers; Task = text + Open/Done, ordered oldest first, Done keeps position; 200 char limit; no edit in v1; delete instant, no confirm/undo.
- (decision) AD-1 paradigm: functional core / imperative shell with unidirectional flow (pure reducer + render from state). Weighed: plain mutable DOM scripting (drifts: UI and storage each mutate), React/Preact (framework overhead for 3 actions, contradicts restraint). Prevents UI code, storage code and tests each owning a copy of task logic.
- (decision) AD-2 all Task mutation only via core reducer; Task shape {id,text,done}; array order is list order. Prevents two owners of ordering/state.
- (decision) AD-3 persistence: single localStorage key umasha.tasks.v1 holding JSON array of Task; one subscriber writes after each state change; read once at startup; storage failure and corrupt data degrade silently to session-only/empty (PRD FR-5). Weighed IndexedDB (overkill), cookies (no). Prevents multiple writers and key/format drift.
- (decision) AD-4 task text rendered only via textContent / DOM APIs, never innerHTML. Prevents stored-XSS via localStorage text.
- (decision) AD-5 validation (trim, reject empty, MAX_TASK_LENGTH=200) lives in core only; input maxlength reads the same constant. Prevents UI and core disagreeing on limits.
- (decision) AD-6 accessible control structure: Complete is a native checkbox labelled by task text; Delete is a separate native button with aria-label; list is ul/li; Done state shown by strike-through plus dimming, not color alone. Prevents divergent a11y and accidental delete (FR-2, FR-3, NFR Accessible).
- (decision) AD-7 delivery: static SPA, no backend, no analytics/telemetry, no network calls with Task data. Single environment (production = static files). Host not chosen.
- (decision) Stack: vanilla TypeScript on Vite via create-vite vanilla-ts starter. Weighed React/Preact/Svelte: rejected for restraint. Chosen as boring, paved path for an intermediate-skill builder.
- (version) Verified via npm registry 2026-10-26: vite 8.3.5 (node ^20.19 || >=22.12), typescript 7.0.2, vitest 5.0.5 (node ^22.12 || ^24 || >=26), create-vite 9.3.1; local node v24.16.0. Not web-checked beyond npm registry.
- (assumption) TypeScript 7.0.2 works with the create-vite vanilla-ts template and Vite 8.3.5; builder should accept the template's pinned TS if it differs.
- (assumption) IDs via crypto.randomUUID (needs secure context: https or localhost); one id function so it can be swapped.
- (assumption) Corrupt or wrongly-shaped stored data is treated as an empty list rather than an error screen.
- (assumption) Hosting is any static host (e.g. GitHub Pages or Netlify); not decided here.
